    Tight-loop wrap aligned to buffer boundaries
    
    setSamplePosition already snaps the current position to bufferSize
    multiples, but the loop wrap compared against the raw loopEnd time. On
    every wrap the alignment ate up to one buffer length, the playhead
    overshot the loop region and any events between the actual loopEnd and
    the aligned position got immediately killed by the sendAllNotesOff that
    follows. Audible stutter on tight loops.
    
    Snap both loop bounds to buffer boundaries and use >= so the wrap fires
    exactly at the block boundary. Far-overshoot case (e.g. seek into a

    to loopStart.

    Piano roll: arrow-key horizontal step lands on the actual 1/N grid
    
    setGridResolution(N) wrote gridResolution = 1/N, but every consumer in
    the file (paint's grid lines, getGridTimeStep, snapTimeToGrid, pencil-

    note." 1/16 of a quarter is a 1/64 note, so calling

    shifted notes by 1/64 per press, which read as random jumps next to

    the math wants. The visual grid, the snap, and the cursor-key step
    now agree.
